# 阳光社区 · 亲子旧物交换平台

社区亲子旧物交换活动的**报名撮合与现场核销**系统。不是单纯的报名列表，而是让每一件物品从 **提交 → 审核 → 撮合 → 预约 → 到场 → 核销 → 交换成功 / 无人交换 / 转捐 / 带回** 全程可追踪，并让社区工作人员、志愿者、家长、公益机构围绕同一件物品协同处理异常。

本版重点实现了**物品实物不符处理与撮合回滚**：家长带到现场的玩具缺少关键零件、与报名照片差异较大或消毒状态无法确认时，志愿者拍照标记问题并**冻结该物品及其关联撮合**；原撮合对象可在**继续交换 / 改为自由交换 / 等待替代物品 / 取消**之间选择；社区工作人员依据现场复核与原始描述决定放行、退回、强化复核、改约、补偿摊位优先级或转人工调解；多次退回的物品与家庭进入强化照片复核、缺件说明流程并影响自动撮合资格。

技术栈：Vue 3 + TypeScript + Pinia + Vue Router + Vite（纯前端，localStorage 持久化，无需后端）。

## 本地启动

### 方式一：Docker（一键启动）

```bash
docker compose up -d --build   # 构建并启动，访问 http://localhost:8080
docker compose down            # 停止
```

### 方式二：Node 本地开发

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，默认 http://localhost:5173
```

其他命令：

```bash
npm run build      # 生产构建（输出 dist/）
npm run preview    # 预览生产构建，默认 http://localhost:4173
npm run typecheck  # vue-tsc 类型检查
npm run smoke      # 端到端冒烟测试（jsdom 模拟四角色完整流程，29 项断言）
```

## 功能地图（按角色）

- **家长**：报名新物品（孩子年龄、物品品类/成色/照片、是否消毒、期望换取类型、参考价值、可到场时间、是否接受公益捐赠）→ 我的物品（状态时间线、入场凭证/冻结凭证提示、强化复核提示、摊位优先级）→ 撮合中心（查看智能推荐、发起/接受/拒绝撮合；**对方物品冻结后四选一回滚**）→ 争议协调（查看问题照片、缺件说明，与社区沟通）。
- **社区工作人员**：物品审核（**强化照片复核队列**：多角度照片+缺件说明重点核对）→ 撮合管理（一键智能撮合，**资格暂停家庭不参与**；冻结/回滚中组合总览）→ 现场总览（冻结组合、到场/成交、自由交换登记含等待替代物品）→ 异常处置台（**现场复核放行 / 确认不符退回 / 转强化复核 / 协调转捐（授权+能力双校验）/ 为对方改约 / 补偿摊位优先级 / 价值争议转人工调解**）→ 活动总结（退回与冻结统计、资格暂停家庭、成功率、捐赠去向）。
- **志愿者**：扫码核销台（输入/扫描核销码 → 核对照片、破损、消毒；**勾选缺件/照片差异/消毒无法确认 → 拍照（≤3 张）+ 缺件说明 → 一键冻结物品与关联撮合**）；冻结待处理看板；上报现场异常；确认预约组合交换完成。
- **公益机构**：查看待接收捐赠、确认接收（占用接收能力，接收前再次校验家长授权与剩余能力）或因能力不足拒收（自动生成异常交由社区协调其他去向）。

## 实物不符与撮合回滚 · 状态规则

1. **冻结**：志愿者在核销页勾选任一实物问题（缺少关键零件 / 与报名照片差异较大 / 消毒状态无法确认），提交后问题物品 `frozen`、关联撮合 `frozen`，**复核期间摊位保留**，取物凭证标记冻结，同时生成「现场实物不符」异常，问题物品累计退回次数 +1。
2. **原撮合对象四选一**（只有非问题方家长可选，问题方不能单方面改写）：
   - **继续交换**：等待社区现场复核比对原始描述，放行后恢复原摊位/时段并正常成交；
   - **改为自由交换**：双方释放原摊位与时段，物品进入自由交换区现场另寻交换；
   - **等待替代物品**：保留到场登记、释放原摊位，社区协调同类替代物品，可在自由交换区现场登记成交；
   - **取消**：**按实际到场情况分别处理**——已到场的保留到场登记（转无人交换/自由交换/带回/转捐候选），未到场的释放预约时段回待撮合池，且不会再与同一问题物品配对。
3. **社区处置**：复核放行（继续或转自由交换区）/ 确认实物不符退回家长（累计 2 次→暂停家庭自动撮合资格）/ 转强化照片复核与缺件说明（重走审核，通过后恢复资格）/ 协调转捐（**家长捐赠授权 + 公益剩余接收能力双校验**，不足时生成异常）/ 为到场一方改约时段（限于家长报名可到场时间）/ 补偿摊位优先权重 / 价值争议转**人工调解**（调解期间双方均不能改写交换结果，办结即最终处置）。
4. **多次退回联动**：物品累计退回 ≥2 次自动要求强化复核；家庭被暂停自动撮合资格后，新报名强制进入强化照片复核+缺件说明流程，且不进入一键智能撮合、不能主动发起撮合（现场自由交换不受限）。

## 验证方式

### 已执行的自动化验证

- `npm run typecheck`：vue-tsc 类型检查通过（0 错误）。
- `npm run build`：生产构建成功。
- `npm run smoke`：jsdom 中执行完整应用，共 **29 项断言全部通过**。除原有 18 项（登录、四角色页面、接受撮合、驳回药品、智能撮合、扫码核销、公益接收等）外，新增覆盖：志愿者勾选「缺少关键零件」+缺件说明后**拍照标记并冻结**、原撮合对象选择**取消**、问题方家长**无法单方面改写**且看到资格暂停提示、社区**未授权转捐被拦截**、价值争议**转人工调解并办结**、复核**确认不符退回**、撮合管理展示**资格暂停家庭与冻结组合**、审核队列展示**强化照片复核**。

### 手工验证路径（建议按顺序体验完整生命周期）

1. **现场冻结**：`volunteer` 登录 → 输入 `SW-1027`（或任一已预约物品核销码）→ 取消「照片一致」勾选并点选「缺少关键零件」→ 上传问题照片、填写缺件说明 → 点击「拍照标记问题并冻结」，右侧出现冻结待处理组合。
2. **家长回滚**：`parent4` 登录 →「撮合中心」可见冻结组合与四种选择 → 分别尝试「继续交换 / 改为自由交换 / 等待替代物品 / 取消」，查看各自对摊位、时段、凭证、自由交换区的影响提示。
3. **社区复核**：`staff` →「异常处置」→ 在实物不符卡片中查看双方到场情况表、问题照片与缺件说明 → 依次尝试「复核放行」「确认不符·退回家长」「转强化照片复核」「协调转捐」（机器人未授权捐赠会被拦截并记录）、「为对方改约时段」「补偿对方摊位优先级」。
4. **人工调解**：在「积木桌价值争议」事件中填写说明并「转人工调解」→ 选择最终处置方案并「办结调解」，验证调解期间物品保持争议状态、任何家长端无改写入口。
5. **资格联动**：`parent3` 登录可见自动撮合暂停提示；`staff`「撮合管理」可见该家庭被排除在一键智能撮合之外；「物品审核」中「积木收纳箱」带强化照片复核提示，审核通过后资格自动恢复；「活动总结」可查看退回/冻结明细与资格暂停家庭。
6. **捐赠双校验**：`parent4` 对无人交换的拼图申请转捐 → `charity` 确认接收（占用能力）；把公益能力点用完后再接收会自动生成「接收能力不足」异常。
7. **阶段推进**：`staff` 各页面顶部的阶段条可将活动从「报名审核 → 撮合配对 → 现场活动 → 活动总结」逐步推进。

- 所有数据保存在浏览器 localStorage（键 `swapmeet-db-v2`），首次打开自动写入种子数据；登录状态保存在 `swapmeet-auth-v1`。升级版本后会自动重新播种演示数据。
- 种子数据包含 29 件物品，覆盖待审核（含强化复核）、待撮合、撮合待确认、已预约、已核销、交换成功、自由交换区、无人交换、已转捐、已带回、未到场、已驳回、**问题冻结、等待替代物品**全部状态，以及进行中/已解决的异常、两起现场实物不符（一起等待替代、一起待对方选择）与一起价值争议。
- 上传的成色照片与现场问题照片均会压缩为 ≤480px 的 dataURL 存入本地；未上传时使用品类图标占位。
