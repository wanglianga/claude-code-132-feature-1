# 阳光社区 · 亲子旧物交换平台

社区亲子旧物交换活动的**报名撮合与现场核销**系统。不是单纯的报名列表，而是让每一件物品从 **提交 → 审核 → 撮合 → 预约 → 到场 → 核销 → 交换成功 / 无人交换 / 转捐 / 带回** 全程可追踪，并让社区工作人员、志愿者、家长、公益机构围绕同一件物品协同处理异常。

技术栈：Vue 3 + TypeScript + Pinia + Vue Router + Vite（纯前端，localStorage 持久化，无需后端）。

## 本地启动

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，默认 http://localhost:5173
```

其他命令：

```bash
npm run build      # 生产构建（输出 dist/）
npm run preview    # 预览生产构建，默认 http://localhost:4173
npm run typecheck  # vue-tsc 类型检查
npm run smoke      # 端到端冒烟测试（jsdom 模拟四角色完整流程，18 项断言）
```

## 功能地图（按角色）

- **家长**：报名新物品（孩子年龄、物品品类/成色/照片、是否消毒、期望换取类型、参考价值、可到场时间、是否接受公益捐赠）→ 我的物品（状态时间线全程追踪）→ 撮合中心（查看智能推荐、发起/接受/拒绝撮合）→ 入场凭证（核销码 + 摊位 + 入场时段）→ 争议协调（与社区围绕物品沟通）。
- **社区工作人员**：物品审核（玩具/绘本/衣物/学习用品/婴童用品放行，危险品/食品/药品/隐私物品驳回并填写原因）→ 撮合管理（一键智能撮合：按年龄段、品类、价值区间、双方期望、摊位容量评分配对；未匹配物品转入自由交换区）→ 现场总览（到场/成交进度、自由交换区现场登记、标记未到场）→ 异常处置台（缺席、实物不符、孩子反悔、价值争议、公益接收不足五类异常的协同处理与办结）→ 活动总结（交换成功率、未到场名单、捐赠去向、争议处理、下一场品类缺口）。
- **志愿者**：扫码核销台（输入/扫描核销码 → 核对照片与实物一致、破损情况、消毒确认 → 通过或转异常）；上报现场异常；确认预约组合交换完成。
- **公益机构**：查看待接收捐赠、确认接收（占用接收能力）或因能力不足拒收（自动生成异常交由社区协调其他去向）。

## 验证方式

### 已执行的自动化验证

- `npm run typecheck`：vue-tsc 类型检查通过（0 错误）。
- `npm run build`：生产构建成功。
- `npm run smoke`：jsdom 中执行完整应用，模拟四个角色登录并遍历核心流程，共 18 项断言全部通过，包括：登录页渲染、家长四页渲染、家长接受撮合、社区驳回药品（含驳回原因）、智能撮合执行、现场总览/异常处置/活动总结渲染、志愿者扫码 `SW-1011` 并完成核销、公益机构确认接收捐赠。

### 手工验证路径（建议按顺序体验完整生命周期）

1. **报名与审核**：`parent1` 登录 →「报名新物品」提交一件玩具 → 切换 `staff` →「物品审核」通过该玩具，并驳回待审核队列中的「儿童感冒药」（药品）与「手持烟花棒」（危险品），填写驳回原因。
2. **撮合与预约**：`staff` →「撮合管理」→「一键智能撮合」生成组合 → `parent2` 登录「撮合中心」接受磁力片撮合 → `parent4` 接受后双方预约成功，自动分配摊位与入场时段 → 家长在「我的物品」查看入场凭证（核销码二维码）。
3. **现场核销与交换**：`volunteer` 登录 → 输入 `SW-1012` 核销点读笔（勾选照片一致、无破损、已消毒）→ `SW-1011` 已被种子数据核销时可在「现场总览」（`staff`）对双方均核销的组合点击「确认交换完成」。
4. **异常协同**：`volunteer` 在核销台对某物品上报「孩子现场反悔」→ `staff`「异常处置台」选择处理方案（带回/转自由交换区）并办结 → `parent` 端「争议协调」可看到处理记录并补充说明；`charity` 拒收捐赠会自动生成「公益接收能力不足」异常。
5. **捐赠与总结**：`parent4` 对无人交换的拼图「申请转捐」→ `charity` 确认接收 → `staff`「活动总结」查看交换成功率、未到场名单、捐赠去向、争议处理与品类缺口分析。
6. **阶段推进**：`staff` 各页面顶部的阶段条可将活动从「报名审核 → 撮合配对 → 现场活动 → 活动总结」逐步推进。

## 数据说明

- 所有数据保存在浏览器 localStorage（键 `swapmeet-db-v1`），首次打开自动写入种子数据；登录状态保存在 `swapmeet-auth-v1`。
- 种子数据包含 23 件物品，覆盖待审核、待撮合、撮合待确认、已预约、已核销、交换成功、自由交换区、无人交换、已转捐、已带回、未到场、已驳回全部状态，以及进行中/已解决的两起异常事件。
- 上传的成色照片会压缩为 ≤480px 的 dataURL 存入本地；未上传时使用品类图标占位。
